# CsvMetricsProcessor

Высокопроизводительный бэкенд-сервис для построчной обработки временных рядов из CSV-файлов, расчета агрегированных метрик (включая локальный расчет медианы) и генерации интегральных отчетов.

Проект спроектирован по канонам **Чистой Архитектуры (Clean Architecture)** с четким разграничением ответственности слоев (**Domain, Application, Infrastructure, API**) и реализацией паттерна **CQRS** (EF Core на запись, чистый Dapper на чтение).

---

## Технологический стек
* **Runtime:** .NET 9
* **Архитектурные паттерны:** Domain-Driven Design (DDD), CQRS, Unit of Work / Repository, Value Objects.
* **База данных:** PostgreSQL 16 (с оптимизированными составными индексами под выборки).
* **Библиотеки и инструменты:**
    * **MediatR** — оркестрация сценариев использования (Use Cases).
    * **Dapper** — быстрое динамическое чтение отчетов с кастингом и округлением типов на стороне СУБД.
    * **CsvHelper** — потоковый построчный парсинг файлов без перегрузки оперативной памяти.
    * **FluentAssertions & xUnit** — покрытие бизнес-логики и Value Objects юнит-тестами (39 тестов).
    * **Docker & Docker Compose** — оркестрация контейнеров бэкенда и СУБД с автоматическим накатом миграций.

## Быстрый запуск всего проекта (включая БД и API)

Все компоненты приложения полностью контейнеризированы. Для запуска вам понадобится только установленный **Docker Desktop**.

1. Клонируйте репозиторий и перейдите в корень решения:
   ```bash
   cd CsvMetricsProcessor
   ```

2. Запустите сборку и развертывание контейнеров одной командой:
   ```bash
   docker compose up -d --build
   ```

3. После успешного запуска откройте интерактивную документацию в браузере:
    **[http://localhost:5000/swagger](http://localhost:5000/swagger)**

> **Примечание:** При первом запуске API автоматически проверит состояние СУБД и применит необходимые миграции (`MigrateAsync()`). База данных разворачивается с нуля полностью автоматически

##  Как запустить проект в режиме локальной разработки (Для дебага)

Если вы хотите вносить изменения в код с мгновенным подхватом изменений (Hot Reload), запускайте Docker в гибридном режиме:

1. Поднимите в Docker **только базу данных PostgreSQL** (она будет тихо работать в фоне):
   ```bash
   docker compose up -d postgres_db
   ```

2. Перейдите в папку проекта API и запустите локальный сервер автоперезагрузки .NET:
   ```bash
   cd src/CsvMetricsProcessorService.API
   dotnet watch
   ```

## Архитектурные особенности, повышающие производительность:
* **Manual Batching (Chunking):** Вставка 10 000 строк из CSV выполняется пачками по 2000 записей с периодическим очищением Change Tracker (`_context.ChangeTracker.Clear()`), что гарантирует минимальное потребление RAM сервером при высокой скорости дисковой записи.
* **Compound Database Indexes:** Для метода №3 настроен составной индекс `HasIndex(x => new { x.FileName, x.Date })`, благодаря которому выборка последних 10 строк конкретного файла выполняется за доли миллисекунд прямо из B-Tree дерева, минуя полный перебор таблицы.
